# Feature 11 plan: Watch face

The steps run in this order. Every command runs from the repo root. The C build and tests run with `cmake -S . -B build && cmake --build build && ctest --test-dir build --output-on-failure`. The Python tools and tests run in the reference venv with `reference/.venv/bin/python`, and the scripts that use the port run with `~/.espressif/tools/python/v6.1/venv/bin/python`. ESP-IDF loads with `. ~/.espressif/tools/activate_idf_v6.1.sh`. The watch is on USB at /dev/cu.usbmodem101, and implement may flash it and run scripts on it. Nobody looks at the screen or touches the watch during implement, so the manual checks wait for the user.

No step changes a file in reference/, context/, core/kissfft/, tests/unity/, tests/detector/, tests/converter/, tests/pads/, tests/model/, firmware/bringup/, firmware/components/, or firmware/detector_check/. In core/ the files of features 3 to 10 stay as they are, except that core/session.h and core/session.c gain sess_took_it() and core/recording_format.md gains the notes of step 11. tools/gen_tables.py, tools/watch_cli.py, tools/compare_session.py, the Makefile, and the root CMakeLists.txt stay as they are. No new file may hold the rate 112.1 in any form, and no code may call bsp_display_start(). Never change a limit or a case in validation.md to make a case pass. If a case can pass only that way, stop and report it.

2. Make the fonts and the icons as in requirements 11, 37, 38, 46, and 47.
   - Download fonts/Proportional/RedHatDisplay/ttf/RedHatDisplay-Bold.ttf and OFL.txt from commit 6bb1048a6402b0076ea04f42951ec66263cd1437 of github.com/RedHatOfficial/RedHatFont into firmware/main/assets/. Download the LICENSE file of lucide-static 0.469.0 from unpkg.com into firmware/main/assets/LUCIDE_LICENSE.txt. Record the SHA-256 hash of the font file in the header comment of the tool.
   - Write tools/gen_face_assets.py. It checks the font file's hash and stops with an error when it differs. It runs `npx --yes lv_font_conv@1.5.3` once for each size with `--bpp 4 --format lvgl --no-kerning --lv-include lvgl.h --font firmware/main/assets/RedHatDisplay-Bold.ttf`. The ranges are 0x20-0x7E for 28, 40, and 56 pixels, and 0x20,0x2D,0x30-0x3A for 96 pixels. The outputs are firmware/main/assets/face_font_28.c, face_font_40.c, face_font_56.c, and face_font_96.c, and the font names are face_font_28 to face_font_96.
   - The tool reads each font file's line_height, base_line, and the adv_w of each glyph from the lv_font_conv output. It writes core/face_metrics.h with FACE_LINE_28 to FACE_LINE_96, FACE_BASE_28 to FACE_BASE_96, and one const array of 95 advance widths for each size, for the characters 0x20 to 0x7E. Each width is (adv_w + 8) >> 4, which is how LVGL 9.5.0 rounds it, and a character the font lacks has width 0.
   - The tool holds the Lucide 0.469.0 path data of activity, minus, vibrate, clock, pill, check, and circle-check-big, split into the ring and the tick, with a comment that names the version. `draw_icon(elements, size_px, stroke)` reads the path commands M, L, H, V, C, S, A, and Z in both cases, and circle and rect elements with rx. It turns each curve and arc into short straight pieces and gives each pixel the coverage clamp(stroke / 2 + 0.5 - d, 0, 1), where d is the distance from the pixel's centre to the nearest piece, so caps and joins come out round. It returns a numpy array of uint8. Each icon is 88 by 88 pixels with a stroke of 88 × 1.5 / 24 = 5.5 pixels.
   - The tool writes firmware/main/assets/face_icons.c and face_icons.h. Each icon is an lv_image_dsc_t with the A8 colour format, a stride equal to its width, and its bytes as a const array. face_icons.h names face_icon_tremor, face_icon_no_tremor, face_icon_arm_moving, face_icon_waiting, face_icon_dose_due, face_icon_check, face_icon_logged_ring, and face_icon_logged_tick.
   - The tool takes `--font`, `--assets`, and `--metrics`, with the repo's paths as defaults, so the tests can write to a temporary folder. `parse_font_output(text: str) -> FontMetrics` reads one lv_font_conv output, and `write_image_c(name: str, pixels: np.ndarray) -> str` gives the C text of one icon.
   - Every generated file starts with a comment that says the tool made it and gives the command. The functions have type hints, and the tool logs with the logging module and holds no `print(`, no `os.path`, and no `except Exception`.
   - Write tests/tools/test_gen_face_assets.py with the cases of check 3. Run `reference/.venv/bin/python tools/gen_face_assets.py`.

3. Write core/look.h and core/look.c as in requirements 8, 10 to 18, 24, 25, 39, 42 to 46, 51, and 61, and tests/look/test_look.c with the cases of check 1.
   - look.h holds the screen size LOOK_W 410 and LOOK_H 502, LOOK_CORNER 60, LOOK_CIRCLE 260, LOOK_OUTLINE 8, LOOK_TOOK_IT_Y 251, and the colours as 0xRRGGBB values. They are LOOK_BG 0xF6F3EE, LOOK_CARD 0xFFFFFF, LOOK_TEXT 0x111315, LOOK_TEXT2 0x5C6265, LOOK_TREMOR 0x1B2E42, LOOK_NO_TREMOR 0x2A7242, LOOK_DOSE 0x6A3D9A, LOOK_ARM 0x26292B, LOOK_WAITING 0x5C6265, LOOK_TOOK_IT 0x173A28, and LOOK_WHITE 0xFFFFFF.
   - The screens are LOOK_HOME, LOOK_MEDICATION, LOOK_LOGGED, LOOK_SESSION, and LOOK_STATUS. The icons are LOOK_ICON_TREMOR to LOOK_ICON_LOGGED_TICK in the order of step 2.
   - `const look_state_t *look_state(face_state_t s)` gives filled, the circle colour, the ink colour of the word and icon, the icon, and the word for each face state, and the Waiting look for any other value.
   - `const look_box_t *look_box(look_screen_t screen, look_item_t item)` gives the box of each item in pixels as x, y, w, h, and its text size. The items are the time, the date, the battery, the circle, the circle's icon, the circle's word, the last tremor line, the cards, the two dose labels and values, the button and its icon and word, the share figure and its line, the block area and its two labels, and the nine status rows. It returns NULL for an item that a screen lacks. `look_tap_box(look_screen_t screen)` gives the tap target, which is the whole screen for Home, the lower half for Medication, and NULL for the others.
   - `int look_line_height(int size)` and `int look_text_width(const char *text, int size)` read core/face_metrics.h. The width is -1 when the text holds a character that the font lacks or a size that is not 28, 40, 56, or 96.
   - `int look_fit_size(const char *text, int box_w, int largest, int smallest)` gives the largest of 96, 56, 40, and 28 from largest down to smallest at which the text fits in box_w, or 0.
   - `size_t look_cut(const char *text, size_t cut_at, size_t cut_len, int box_w, int size, char *out, size_t out_size)` copies the text when it fits. Otherwise it keeps the part before cut_at and the part after cut_at + cut_len, and it keeps the longest start of the cut part with "..." after it that fits. It returns the length, or 0 when even an empty cut part does not fit.
   - The colours and the layout are const data, so the file has no static data that changes.

4. Write core/screens.h and core/screens.c as in requirements 4, 5, 7, 21, 22, 24 to 26, and 54 to 57, and tests/screens/test_screens.c with the cases of check 1.
   - The constants are SCR_SETTLE_US 1000000, SCR_WAIT_US 1000000, SCR_LOGGED_US 3000000, and SCR_IDLE_US 300000000. The flags are SCR_ACCEPTED, which asks for the press and the tap tone, SCR_TOOK_IT, which asks for a dose, and SCR_CHANGED.
   - The functions are `void scr_init(scr_t *s, int64_t now_us)`, `unsigned scr_tap(scr_t *s, int x, int y, int64_t now_us)`, `unsigned scr_button(scr_t *s, bool down, int64_t now_us)`, `unsigned scr_logged(scr_t *s, int64_t now_us)`, `unsigned scr_tick(scr_t *s, int64_t now_us)`, and `look_screen_t scr_screen(const scr_t *s)`.
   - scr_button() takes one read of the BOOT button. A press counts on the second read in a row that finds the button down after a read that found it up.
   - The caller owns the state, and the file has no static data that changes.

5. Add sess_took_it() to core/session.h and core/session.c, and write core/view.h and core/view.c, as in requirements 6, 14, 24 to 33, 48 to 53, 62, and 63. Add the new session cases to tests/session/test_session.c and write tests/view/test_view.c with the cases of check 1.
   - `unsigned sess_took_it(sess_t *s, int64_t now_us)` returns 0 when dose_took_it() refuses. Otherwise it returns the new flag SESS_DOSE_LOGGED, which is 8u, and SESS_FACE_CHANGED when face_set_dose_due(false) changes the shown state.
   - view.h holds view_t and view_input_t. view_t holds the shown face state, the time, the date, the last tremor line, the due flag, the two Medication entries, the Logged view's next line, the next dose time and the last tremor time as short texts for the SCREEN_VIEW line, the share figure, its line, the whole percent or -1, the block count, each block's hollow flag and percent, the oldest block's start time, the nine status values, the battery text of Home, the tone setting, the count of dose tones, and the count of accepted doses. Each text that may be cut carries its cut_at and cut_len for look_cut().
   - view_input_t holds the battery state, the battery millivolts and percent, the uptime in seconds, whether an answer has come, the last stretch, rate, and run time, the recording flag, the firmware version, the table hash, the tone setting, and the two counts.
   - `void view_build(view_t *v, const sess_t *s, const view_input_t *in, int64_t now_us)` fills the view. It turns a timer value into local time with the dose clock's offset, and it finds the weekday, day, and month from the days since 1970 with integer arithmetic.

6. Write core/tone.h and core/tone.c as in requirement 59, and tests/tone/test_tone.c with the cases of check 1.
   - The constants are TONE_RATE 16000 and TONE_PEAK 9830, which is 30 percent of 32767 rounded down. The kinds are TONE_TAP and TONE_DOSE.
   - `size_t tone_length(tone_kind_t kind)` gives the length in samples. `size_t tone_fill(tone_kind_t kind, size_t start, int16_t *out, size_t n)` writes samples start to start + n - 1 of the pattern, or fewer at its end, and returns the number written. Each sample is sinf() of the tone's phase times the peak times the fade, rounded to the nearest whole number, so the result does not depend on how the caller splits the pattern.
