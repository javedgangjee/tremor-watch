# Feature 10 plan: Laptop tools

The steps run in this order. Every command runs from the repo root. The Python tools and tests run in the reference venv with `reference/.venv/bin/python`, except watch_cli.py, which needs pyserial and runs with `~/.espressif/tools/python/v6.1/venv/bin/python`. The watch is on USB at /dev/cu.usbmodem101 and lies still on a table with feature 9's firmware flashed. Nobody can look at its screen or touch it during the loop.

No step changes a file in reference/, context/, firmware/, core/kissfft/, tests/unity/, tests/firmware/, tests/pads/, tests/detector/, or tests/converter/, apart from the session report that the validate stage writes to tests/firmware/record_session.md. In core/ only replay.c and recording_format.md change. tools/gen_tables.py, the Makefile, and the three CMakeLists.txt files stay as they are. No new file may hold the rate 112.1 in any form. Never change a limit or a case in validation.md to make a case pass. If a case can pass only that way, stop and report it.

1. Add the recording input to core/replay.c as in requirements 7, 8, 11, and 23 to 26.
   - The usage becomes `replay --pads FILE` or `replay --recording FILE [--samples OUT]`, and any other form prints both lines and exits with code 1. The PADS functions and their output stay byte for byte as they are.
   - Include reading_time.h, pipeline.h, window.h, and imu_units.h. Keep the state in static data, which are an rt_state_t, a pipe_t, one window, and a burst buffer of 256 readings. A T line with a count above 256 counts as a bad line.
   - Read lines with fgets() into a buffer of 1024 characters. A longer line counts as a bad line, and replay reads on to its newline. Drop a carriage return and a newline at the end.
   - Parse the B, S, T, and R lines with a strict reader that accepts exactly the patterns in core/recording_format.md. Each number is a run of digits, with a leading minus sign only where the pattern allows one, and it must fit its type.
   - Before the first B line replay skips every line. A B line with a new boot ID calls rt_init() and pipe_init(), drops any burst it holds, and clears the pending start. A B line with the same boot ID changes nothing.
   - An S line whose stretch number is above every stretch number of the boot so far sets the pending start to its first reading. A T line first passes on the burst that replay holds, then becomes the held burst. Each R line joins the held burst when its number is the next one. A burst passes on only when it holds its count of R lines in order, and otherwise it is dropped and counted. The next B line and the end of the file also pass on the held burst.
   - To pass on a burst, replay calls rt_burst() with the overflow flag set when the burst's first reading equals the pending start, and it then clears the pending start. It fills a pipe_part_t with the flags, rt_current()'s stretch number and rate, the stamp, the first reading, and the count, and calls pipe_part() with the stamp as now_us. Unless the result has PIPE_DROP, it calls pipe_push() with each reading's three gyroscope counts through imu_gyro_dps(). It then calls pipe_window() until it returns false, runs det_run() on each window, takes the code from res_from_answer(), and prints the row.
   - The CSV header is `boot,stretch,first,t0_us,rate_uhz,window,time_us,code,mfcc_1,...,mfcc_12,pred_tremor_proba,below_tremor_power,freq_peak,pred_arm_at_rest,pred_tremor_checked`. stretch, first, t0_us, and rate_uhz come from pipe_stretch(). time_us is the time that pipe_window() gives. The numbers use %.9g for the 12 numbers and the peak and %.17g for the probability and the low-frequency sum, as the PADS rows do.
   - With `--samples OUT`, replay writes `boot,stretch,sample,gyroscope_x,gyroscope_y,gyroscope_z` with %.9g. It writes samples 0 to 399 for window 0 and samples 100n + 300 to 100n + 399 for each later window n.
   - At the end it writes `replay: lines=<n> bad=<n> dropped_bursts=<n> boots=<n> stretches=<n> windows=<n>` to the standard error. It exits with code 1 when the file cannot be opened or read, and when no B line was found, with a message that says so.
   - The header comment describes both inputs, the overflow rule of requirement 23, and the skip rules of requirement 24.
   - replay already links tremor_core and builds with the warning flags and -ffp-contract=off, so no CMake file changes.

3. Write tools/watch_cli.py and tests/tools/test_watch_cli.py as in requirements 1, 2, 14, and 33 to 36, with the cases in validation.md check 4.
   - The functions are `clock_command(now_utc: datetime, offset: timedelta) -> str`, `schedule_command(name: str | None, times: list[str]) -> str`, `tone_command(on: bool) -> str`, `session_command() -> str`, `open_port(port: str, reset: bool) -> Any`, `send_command(ser: Any, command: str, first_line_s: float = 2.0, answer_s: float = 5.0, on_line: Callable[[str], None] | None = None) -> int | None`, `record(port: str, out: Path, minutes: float | None) -> int`, and `main(argv: list[str] | None = None) -> int`.
   - schedule_command() raises ValueError for a name of 0 or more than 20 characters, a name character other than a letter, a digit, `-`, `.`, `/`, or `+`, a time that is not two digits, a colon, and two digits from 00:00 to 23:59, more than six times, and a time given twice. It writes the minutes in the order given.
   - send_command() reads until one whole line arrives or first_line_s passes, writes the command and a newline once, and reads until a line `A,<n>,<r>` with the command's number arrives or answer_s passes. It passes every line it reads to on_line when one is given. It returns r, or None when no answer came.
   - record() writes to a gzip file with the laptop time from time.monotonic() counted from the open, three decimals, a tab, and the text. It writes every line it reads. Right after the first B line it writes `> <command>` for clock_command() of the laptop's time and offset, and it sends the command with send_command() with a first_line_s of 0, because it is already reading the port. It passes an on_line that writes each line to the file. It stops at `--minutes` or at KeyboardInterrupt and closes the file.
   - main() logs with the logging module and exits with code 2 for an argument that schedule_command() refuses, before any port opens. It sets the SIGINT handler to signal.default_int_handler, so Ctrl-C and `kill -INT` stop a recording even when a shell starts it in the background with SIGINT ignored.

## Changes during implement

1. replay leaves out the last burst of the file without counting it as dropped when its R lines are in order but fewer than its count. The plan passed it on at the end of the file and so dropped and counted it. tests/firmware/record_log.txt.gz ends with a T line that has no R lines, because the capture stopped there, and check 3 case 10 expects dropped_bursts=0 for that log. A last burst whose R lines break their order still counts. The drop log now gives dropped_bursts=2.
2. replay also checks the W, F, D, and A lines against their patterns and counts a line that breaks one as a bad line. The plan named the strict reader for the B, S, T, and R lines only, but requirement 24 counts any line that starts with a record letter and a comma and breaks its pattern. A broken B line counts as bad only after the first B line.
3. Every B line first passes on the burst that replay holds, and only then does a new boot ID start the time rule and the pipe again. The plan said both that a B line passes on the held burst and that a new boot drops it. Passing it on first gives a whole burst to the boot it belongs to, and a burst that a reset cut short is still dropped and counted.
4. tests/replay/recording_maker.py holds more helpers than the five that the plan names. They are table_hash(), rate_burst(), burst_lines(), t_lines(), t_line_at(), stretch_rate(), with_second_stretch(), and summary(). tests/tools/test_compare_session.py builds its clean recording with with_second_stretch(), so it uses the same recording as check 3 case 3.
5. In compare_session.py the T lines of a Boot are the T lines whose R lines all came in order, and the gaps are the gaps in their numbers. So a burst that lost R lines ends a checked part, as check 7 item 3 expects for the burst at reading 8019 of the drop log.
6. compare_session.py reads "a gap or the start of the recording lies in that stretch or in the stretch before it" with the watch's stretches. A gap lies in a stretch when its first missing reading lies within the stretch's readings. For a replay stretch with no matching S line, the stretch is the watch's stretch that holds replay's first reading. A W line of a stretch whose first reading the recording does not hold, other than the lowest stretch of its boot, counts as not checked because of a gap when such a gap or start lies there.
7. The report of compare_session.py lists each replay stretch that has no S line with its replay rate, and it counts the windows of such a stretch apart from the watch's W lines that were not checked. The plan had no place for these windows, and the drop log has 146 of them.
8. compare_session.py stops a run with its own StopRun exception, and main() turns it into exit code 1. This lets the tests read main()'s exit code for a recording with no B line.
9. watch_cli.py's record() opens the port again with no reset after a read error, as record_run.py does, because the port can vanish while the watch resets. It also returns 1 before it opens the port when the output folder does not exist, it opens the gzip file in "x" mode so it can never write over a file, and it keeps recording after a clock command that failed.
10. watch_cli.py's main() exits with code 2 for `schedule --off` with a name or a time, and for `schedule` with neither a name nor `--off`. The plan did not say how the tool treats these forms.
11. The fake port of check 4 case 16 gives the A line of the second and third ports only after the write. With every line ready from the start, the wait for the first whole line reads the lone A line before the command goes out, so send_command() could never return 3 or 5. The test of main() sets the waits to 0.1 and 0.2 seconds so it runs fast.
12. The watch trial also ran check 10 item 6 with `--port /dev/does-not-exist`. It exits with code 2 and no port error, which shows that the tool opens no port.
