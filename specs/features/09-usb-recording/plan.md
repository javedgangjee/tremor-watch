# Feature 9 plan: USB recording and commands

The steps run in this order. Every command runs from the repo root. Load ESP-IDF in each shell with `. ~/.espressif/tools/activate_idf_v6.1.sh`. The watch is on USB at /dev/cu.usbmodem101 and lies on a table. Nobody can look at its screen or touch it during the loop. If the port stops answering, run the USB reset helper that the stage prompt names.

No step changes a file in reference/, context/, core/kissfft/, tests/unity/, tools/, firmware/bringup/, firmware/components/, or firmware/detector_check/. No step changes an existing .c or .h file in core/, the Makefile, or an existing file in tests/ other than tests/CMakeLists.txt. firmware/main/pipeline_task.c and firmware/main/screen_task.c stay as they are. tests/firmware/table_run.py, tests/firmware/pipeline_run.py, their test files, and their logs and reports stay as they are. No new file may hold the rate 112.1 in any form. Never change a limit or a case in validation.md to make a case pass. If a case can pass only that way, stop and report it.

1. Write core/record.h and core/record.c as in requirements 26, 27, 30, 31, and 36.
   - The header includes stdbool.h, stddef.h, stdint.h, dose.h, face.h, and window.h. It defines REC_LINE_MAX (128), which holds the longest line and its zero byte, and REC_COMMAND_MAX (127). It defines REC_CLOCK_MIN_US (1577836800000000) and REC_CLOCK_END_US (4102444800000000), which are 1 January 2020 and 1 January 2100 in UTC, and REC_OFFSET_MIN (-720) and REC_OFFSET_MAX (840).
   - `rec_cmd_t` has REC_CMD_UNKNOWN (0), REC_CMD_CLOCK (1), REC_CMD_SCHEDULE (2), REC_CMD_SESSION (3), REC_CMD_TONE (4), and REC_CMD_EMPTY (5). `rec_result_t` has REC_DONE (0), REC_UNKNOWN (1), REC_BAD_FORMAT (2), REC_REFUSED (3), REC_NOT_STORED (4), and REC_BUSY (5). `rec_command_t` holds the kind, `int64_t utc_us`, `int32_t offset_min`, a dose_schedule_t, and `bool tone_on`.
   - The line functions are `size_t rec_boot(char *buf, size_t size, uint32_t boot_id, uint32_t reset_cause, uint32_t version, const char *hash)`, `size_t rec_stretch(char *buf, size_t size, uint32_t stretch, uint64_t first, int64_t t0_us, uint32_t rate_uhz, uint32_t range_dps)`, `size_t rec_burst(char *buf, size_t size, uint64_t first, uint32_t count, int64_t stamp_us)`, `size_t rec_reading(char *buf, size_t size, uint64_t number, const int16_t gyro[3], const int16_t accel[3])`, `size_t rec_window(char *buf, size_t size, uint32_t stretch, bool has_window, uint32_t window, res_code_t code, double prob, double below, float peak_hz)`, `size_t rec_face(char *buf, size_t size, int64_t time_us, face_state_t state)`, `size_t rec_dose(char *buf, size_t size, const dose_entry_t *dose)`, and `size_t rec_reply(char *buf, size_t size, rec_cmd_t command, rec_result_t result)`. Each writes one line with no newline and returns its length, or 0 when the line and its zero byte do not fit.
   - `rec_result_t rec_parse_command(const char *line, rec_command_t *out)` reads one command line without its newline and drops one carriage return at its end. It sets out->kind even when it refuses the line, so the answer can name the command. A line longer than REC_COMMAND_MAX gives REC_CMD_UNKNOWN and REC_BAD_FORMAT. An empty line gives REC_CMD_EMPTY and REC_DONE. The parser checks the format and the ranges of requirement 30 and the name rule of requirement 34. It leaves a time given twice to dose_set_schedule().
   - `int64_t rec_clock_offset_us(int64_t utc_us, int32_t offset_min, int64_t stamp_us)` returns utc_us + offset_min × 60,000,000 - stamp_us.
   - record.c holds no static data that changes and no table of pointers. Add record.c to both source lists in core/CMakeLists.txt with the warning flags of the other project files.
   - Write tests/record/test_record.c with the cases in validation.md check 1, and add test_record to tests/CMakeLists.txt in the way test_window is added.

9. Rewrite firmware/main/usb_task.c as in requirements 1, 16, 23 to 32.
   - At start it installs the usb_serial_jtag driver with a send buffer of 4096 bytes and a receive buffer of 512 bytes, with ESP_ERROR_CHECK. It takes the boot ID from esp_random() and the reset cause from esp_reset_reason(), formats the B line with FIRMWARE_VERSION and TABLE_HASH, keeps it, and writes it. It then writes `START uptime_us=<t>` and sends its TASK line.
   - `write_line()` adds a newline and calls usb_serial_jtag_write_bytes() with a wait of 0. A line that does not fit counts as a port drop and marks the port as broken. While the port is broken, the next line first brings the kept B line and the kept S line, if a stretch has started, in that order. The port is whole again when all of them fit, and each such time counts as a restart. The task counts the bytes that the driver took.
   - The loop waits up to 10 milliseconds on g_record_queue. For a record part with RT_NEW_STRETCH it keeps the stretch number, the first reading, and the stamp as t0, and it writes and keeps the S line with the part's rate, which may be 0. For a part with RT_RATE_SET and no RT_NEW_STRETCH it writes and keeps the S line again with the kept first reading and t0 and the new rate. The range is IMU_GYRO_RANGE_DPS. For a first part it writes the T line with burst_count. It then writes one R line for each reading, with the gyroscope counts from axes 3 to 5 and the accelerometer counts from axes 0 to 2.
   - It then writes every line from g_line_queue with no wait, and it reads the received bytes with no wait. It builds command lines of up to REC_COMMAND_MAX characters. A longer line is read to its newline and answered with `A,0,2`. At each newline it takes the timer value as the stamp and calls rec_parse_command(). It ignores REC_CMD_EMPTY. It answers a refused line itself with rec_reply(). It sends a good command to g_state_queue as STATE_MSG_COMMAND with the stamp in at_us and no wait, and it answers 5 when the queue is full. It counts every line that is not empty as a command and every line that it answers itself as a bad command.
   - Once a minute it writes `USB_MINUTE minute=<m> line_drops=<total> port_drops=<total> restarts=<total> bytes=<total> commands=<total> bad_commands=<total> stack_free=<bytes>`, where stack_free comes from uxTaskGetStackHighWaterMark().
   - usb_send() and send_task_line() keep their code. No file in firmware/main names printf, puts, putchar, fputs, or fwrite, even in a comment.

## Changes during implement

1. core/record.c does not pass the probability and the low-frequency sum straight to snprintf() with %.17g. The watch's C library, picolibc, gives the shortest text that reads back as the same double for %.17g, but the laptop's C library gives all 17 digits. So window 0 of check 1 case 6 gave 0.00027784726790546481 on the laptop where the case and the watch give 0.0002778472679054648. record.c now finds the fewest digits from 1 to 17 that read back as the double and lays them out as %.17g does. All 3592 numbers in tests/firmware/pipeline_log.txt are this text, 23,602 test values matched Python's shortest text on the laptop, and the W lines matched the ANSWER lines on the watch in the trial.
2. The USB task calls esp_rom_install_channel_putc(2, NULL) before it installs the driver. With the second console off, the ROM's printf still wrote to the USB port, and ESP-IDF's early log and its log from interrupts use it. The first trial showed the line "E (1069) spi_common: ..." after the B line. Without the ROM's channel, that text goes to UART0 only, as requirement 23 intends.
3. main.c makes g_record_queue in PSRAM with xQueueCreateWithCaps(). With the queue in internal memory, the display driver could not get its internal transfer buffer at boot and logged "Failed to allocate priv TX buffer". With the queue in PSRAM the error did not come back in three boots, before the change of item 2 moved such text off the USB port.
4. The word "puts" in two comments that were there before, in firmware/main/CMakeLists.txt and firmware/main/tasks.h, became "places", so check 4 item 3 prints nothing.
5. A record_msg_t carries the rt_burst() flags on the first part only, as a sensor_msg_t does, so a burst of more than 16 readings never writes its S line twice. sensor_task.c also includes string.h for memcpy().
6. The USB task keeps up to REC_COMMAND_MAX characters and one carriage return of a command line. rec_parse_command() drops the carriage return and then checks the length, so a command of 127 characters may end with a carriage return and a newline, as requirement 30 says.
7. record_run.py judges only the lines from the first B line on. In the trial, 110 lines came before the B line, and some of them were T lines from before the reset that the laptop still held. Its capture also reads 2 seconds more after the last minute lines, so the R lines of the last bursts arrive.
8. command_run.py writes a "> RESET" line at each reset, and the judge splits the log into boots at these lines.
9. Check 4 item 9's third command prints four lines that read "# default:". ESP-IDF v6.1 writes this line before each option that still has its default value, and the console change moved three such options. The same lines came back when sdkconfig was made again from sdkconfig.defaults. No option outside the console and the USB Serial/JTAG port changed. validation.md is unchanged, so the validate stage decides this case.
10. record_run.open_port() opens the port with DTR high and RTS low and then drops DTR when it must not reset the watch. The chip resets while RTS is high and DTR is low, and pyserial sets DTR before RTS when it opens a port. So a port opened with both lines low reset the watch in the first drop trial.
11. drop_run.py reads the first line after it opens the port again and writes it as the script's own line "> PARTIAL <text>" when it breaks the format. When the port closes, the laptop drops the bytes it holds, and in the trials these ended in the middle of a line, so the first line after the open was the rest of an R line. The watch wrote that line whole.
12. In the drop trials the laptop also lost about 33 readings of lines when it closed the port, even when the script closed it just after a burst. So the T numbers show two gaps, one from the laptop at the close and one from the watch's drops, and check 10 item 6 fails as written because it allows one gap. The watch's side held, with about 7480 port drops, one restart, and the B and S lines at its gap. validation.md is unchanged, so the validate stage decides this case.
13. write_line() in usb_task.c returns after it brings the kept lines back when the line it was given is the kept S line or the kept B line, so a new S line after a drop is not written twice.
