# Feature 14 requirements: Record button

## From the project documents

1. The viewer has a Record button. The button starts `tools/watch_cli.py record`, a second press stops it as Ctrl-C does, and the viewer then opens the saved file. This comes from the viewer paragraph in the build spec's USB recording section and the roadmap entry for feature 14.
2. The viewer never opens the watch's port itself, so tools/watch_cli.py stays the only program that talks to the watch, and its reset, clock, and no-overwrite rules still hold. This comes from the viewer paragraph and the roadmap entry.
3. `watch_cli.py record --out FILE` resets the watch, saves every line to a gzip file, and sends the clock command after the B line of each boot. It refuses to write over a file that exists. It stops at SIGINT, SIGTERM, or SIGHUP and closes the file whole in a finally block. SIGINT gives the same path as Ctrl-C. It waits for the port while the cable is out. It returns 0 when the last boot's clock command got result 0, and 1 when the file exists, when no B line came, or when that clock command failed. A port that cannot be opened at the start raises an error before the file is made, so the tool exits with code 1 and a traceback. It writes its messages to the standard error through logging. This comes from tools/watch_cli.py and specs/tech-stack.md.
4. watch_cli.py needs pyserial, which the reference venv lacks, so it runs with the ESP-IDF Python at `~/.espressif/tools/python/v6.1/venv/bin/python`. This comes from specs/tech-stack.md.
5. The saved file is a recording in the form of the Saved recordings section of core/recording_format.md. The viewer shows it with feature 12's reader and page, and every rule of feature 12 for showing a file still holds. This comes from core/recording_format.md and specs/features/12-recording-viewer/requirements.md.
6. A session lasts one to two hours. This comes from specs/mission.md.
7. Nothing in firmware/, core/, reference/, tools/, tests/, or context/ changes. The detector, its stored numbers, watch_cli.py, and the EDF export stay as they are. This comes from CLAUDE.md and the instructions for this run.
8. The window keeps every Electron setting of feature 12's requirement 22. This comes from specs/features/12-recording-viewer/requirements.md.

## Not covered by the project documents

Each item below is a choice that the build spec, specs/, and the existing code leave open.

9. This requirement replaces the words "reads saved files only" in feature 12's requirement 5 and in the Recording viewer section of specs/tech-stack.md. The viewer may start one child process, which is `watch_cli.py record`, and no other program. It still never opens the watch's port, and no file in viewer/src/ or viewer/scripts/ holds `serialport`, `/dev/cu`, or `/dev/tty`, so feature 12's check 1 case 26 still holds. 10. The process handling lives in viewer/src/lib/recorder.js. Like the other modules in viewer/src/lib/, it imports only Node's built-in modules with the `node:` prefix and files that start with `./`, so `node --test` runs its tests with no node_modules. viewer/src/main.js joins it to the window, the IPC, and the quit, and the page only shows the button and the status. The agent decided this on 2026-10-28, and the user has not reviewed it yet.

11. The viewer runs watch_cli.py with the Python that the environment variable TREMOR_PYTHON names, or with `~/.espressif/tools/python/v6.1/venv/bin/python` when TREMOR_PYTHON is not set. It finds watch_cli.py at tools/watch_cli.py in the repo from its own folder, because the viewer runs from the repo and is never packaged, as feature 12's requirement 15 says. Before it starts the child, it checks that the Python exists and can run and that watch_cli.py exists. When either check fails, the page shows one plain message that names the path, and for the Python it also names TREMOR_PYTHON. The agent decided this on 2026-10-28, and the user has not reviewed it yet.

12. The viewer starts the child with child_process.spawn(), the Python as the program, and the argument array `[<repo>/tools/watch_cli.py, 'record', '--out', FILE]`, with no shell. The child runs in the repo root with the viewer's environment plus PYTHONUNBUFFERED=1. Its standard input is closed, and its standard output and standard error are read to the end, so the child never blocks on a full pipe. The child is not detached, so Ctrl-C in the terminal that started the viewer reaches watch_cli.py too and stops it cleanly. The viewer passes no `--port`, so watch_cli.py uses its default port. It passes no `--minutes`, so a recording runs until Stop, because a session lasts one to two hours and the person decides when it ends. The agent decided this on 2026-10-28, and the user has not reviewed it yet.

13. Recordings go to the folder `recordings/` at the repo root, which .gitignore leaves out, or to the folder that the environment variable TREMOR_RECORDINGS names. A relative TREMOR_RECORDINGS resolves against the folder the command ran from, as FILE does. The viewer makes the folder when it is missing. A file is named `tremor-YYYY-MM-DD-HHMMSS.txt.gz` from the laptop's local time when Record is pressed. When that name is taken, the viewer adds `-2`, then `-3`, and so on, before `.txt.gz`. The viewer never passes a path that exists, and watch_cli.py refuses one anyway, so no recording is ever written over. There is no Save dialog, because it would delay the start and the name already says when the recording began. The agent decided this on 2026-10-28, and the user has not reviewed it yet.

14. The recorder has three states, which are idle, recording, and stopping. One button shows "Record" when idle, "Stop" while recording, and "Stopping" with the button turned off while stopping. A press of Stop while stopping does nothing, and a second call to stop gives the same wait and sends no second signal. A start while a recording runs is refused. While recording, the page shows the time since the start as h:mm:ss, updated each second, and the last line that watch_cli.py wrote to its standard error, such as "The watch set its clock.". The agent decided this on 2026-10-28, and the user has not reviewed it yet.

15. Stop sends SIGINT to the child once, which watch_cli.py handles as Ctrl-C, and waits for the child to close. watch_cli.py reads the port with a timeout of 0.5 seconds and sleeps 0.2 seconds at a time while the port is gone, so a clean stop takes about a second. When the child has not closed 10 seconds after SIGINT, the viewer sends SIGKILL and says so. The agent decided this on 2026-10-28, and the user has not reviewed it yet.

16. When the child closes, whether after Stop or on its own, the viewer acts on how it ended. The agent decided this on 2026-10-28, and the user has not reviewed it yet.
    - With exit code 0 the viewer opens the file and the status gives watch_cli.py's line "Saved N lines to FILE.".
    - With another exit code and a file that did not exist before the start, the viewer opens the file and the status gives "watch_cli.py stopped with code N: LINE". watch_cli.py closes its file in a finally block on every path that ends with an exit code, so the file is whole. For example, a recording whose last clock command failed is still a whole recording. A file with no B line opens with feature 12's plain message.
    - With another exit code and no file, the viewer opens nothing, and the status gives "watch_cli.py stopped with code N: LINE". This is what happens when no watch is on the port, because watch_cli.py cannot open the port and stops within about a second.
    - When a signal ended the child, the viewer opens nothing. The status names the signal and, when the file exists, gives its path and says it may be cut short. The person can still open it with Open, and feature 12's reader reads a cut file up to the cut.
    - LINE is the last line that watch_cli.py wrote to its standard error, leaving out the lines that start with "Saved " and "The recording was stopped", which record() writes on every stop. With no other line, LINE is the last line. When LINE holds "No module named 'serial'", the status adds that this Python has no pyserial and that TREMOR_PYTHON can name the ESP-IDF Python.
    - The page keeps a failure message until the next press of Record.

When the viewer itself crashes, watch_cli.py goes on recording, and Ctrl-C in the viewer's terminal stops it cleanly, as requirement 12 says. 20. `--record-for SECONDS` runs a recording with no person. It needs `--capture OUT.png` and no FILE, and SECONDS is a whole number from 1 to 86400. It starts the recording through the same main-process function as the button, stops it after SECONDS through the same stop function, and then opens the file and captures it as feature 12's requirement 23 says. OUT.json also holds `recording`, with the file path, the exit code, the signal, and the status text, and the page's report holds the status text the page showed. The exit code is 0 when watch_cli.py exited with code 0 and the file was drawn, 1 when the recording failed or its file could not be shown, and 2 as before. parseArgs() returns recordFor, which is null without the option, and the usage line gains `[--record-for SECONDS]`. Feature 12's check 1 case 23 gains `recordFor: null` in its expected objects for this reason. The agent decided this on 2026-10-28, and the user has not reviewed it yet.
